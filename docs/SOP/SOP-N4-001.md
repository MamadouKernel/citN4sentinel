# SOP-N4-001 : Démarrage et Arrêt complet de N4 Sentinel

## 1. Objectif
Cette procédure standardise les opérations de démarrage et d'arrêt de N4 Sentinel, en respectant les dépendances entre les composants métiers et en tenant compte des règles de sécurité (SEC-009, SEC-001) et d'orchestration (FR-031).

## 2. Périmètre
S'applique à l'environnement de production.

## 3. Prérequis
- Accès administrateur N4 (avec Second Facteur MFA activé).
- Le compte de l'opérateur ne doit pas avoir son mot de passe expiré.
- Aucun job conditionnel en conflit ne doit être en cours (bloqué par SequenceValidator).

## 4. Procédure de Démarrage Complet
1. **Lancement du workflow** : Depuis l'interface d'administration, sélectionner le workflow `DEMARRAGE-COMPLET`.
2. **Exécution des étapes** : L'orchestrateur démarrera les composants dans l'ordre de leurs dépendances, par exemple : Base de données -> Services Backend -> Interfaces.
3. **Recette technique** : Vérifier dans l'interface de surveillance que tous les composants affichent le statut "Prêt".
4. **Validation finale** : Un validateur (autre que l'opérateur) doit approuver la disponibilité du système.

## 5. Procédure d'Arrêt Complet
1. **Lancement du workflow** : Sélectionner `ARRET-COMPLET`.
2. **Exécution** : Le système suspendra d'abord l'arrivée de nouvelles requêtes, puis arrêtera les composants dans l'ordre inverse des dépendances.
3. **Vérification** : S'assurer que tous les processus N4Sentinel sont bien arrêtés.

## 6. Risques et Rollback
- En cas de blocage d'un composant, utiliser l'option `OperationPartielle` pour forcer l'état ou redémarrer le sous-ensemble fautif.
- Consulter le journal d'audit pour diagnostiquer les erreurs de séquence.
