# SOP-N4-002 : Bascule Center (Failover)

## 1. Objectif
Ce document décrit la procédure opérationnelle pour réaliser une bascule (failover) du composant N4 Center, en s'assurant que le nouveau Center prend correctement le relais.

## 2. Périmètre
S'applique à l'environnement de production.

## 3. Prérequis
- Un composant N4 Center actif et un passif.
- Le validateur/opérateur initiant l'action doit disposer des droits suffisants avec 2FA validé.

## 4. Procédure de Bascule (BASCULE-CENTER)
1. **Initialisation** : Exécuter le workflow `BASCULE-CENTER` via l'interface d'orchestration.
2. **Arrêt contrôlé** : Le Center actif actuel passe en état suspendu puis est arrêté.
3. **Synchronisation** : Attendre la validation de la synchronisation (règles de Readiness).
4. **Promotion** : Le Center passif est promu en tant que Center actif.
5. **Recette technique** : Vérification des journaux et ping applicatif.
6. **Validation** : Clôture du workflow avec un compte-rendu dans le journal d'audit.

## 5. Rollback
Si le nouveau Center ne parvient pas à démarrer (timeout ou erreur fatale dans les logs) :
- Exécuter la procédure de Rollback pour redémarrer l'ancien Center.
- Extraire la session de diagnostic (Sprint 6) pour analyse.
